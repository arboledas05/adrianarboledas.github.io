Course project · module 5163 · pair · Nov 2026

Built in the AWS Management Console, as the brief requires; the pair's optional extra is a CloudFormation template (Infrastructure as Code), written by my partner.

My part: the design defence (9 case questions on security, maintenance, audit and cost) and a monitoring and audit demo in my own AWS Learner Lab with CloudTrail, CloudWatch, AWS Config and VPC Reachability Analyzer.

Inspector

Select a part of the diagram to see what it does.

Console

  1. Run an action: each step appears here.
  1. Customers reach the web tier from the internet, through its security group. The web tier is in a public subnet.
  2. The web tier calls the app tier, and the app tier queries the data tier. Both are in private subnets.
  3. A security group sits in front of each tier and controls which tier can talk to which.
  4. A NAT lets the private tiers download OS updates, outbound only. Nothing can reach them from the internet.

In short

  • One VPC (10.20.0.0/16) with three tiers (web, app and data) across two Availability Zones
  • Two subnets per tier: public for the web tier, private for the app and data tiers (one per Availability Zone; the diagram is simplified)
  • A security group per tier controls which tier can talk to which, and every resource is tagged
  • A NAT, so the private tiers can only go out to the internet for OS updates

Production bug: lost conversions

  1. Symptom Google Ads recorded far fewer conversions than the leads that really arrived (Sep 2026: 4 conversions recorded vs about 20 real leads)
  2. Root cause the site's Content-Security-Policy blocked the tracking
  3. Fix added the missing hash and origins to the policy; tracking moved to Consent Mode v2
  4. Result verified in production: the conversion requests go through

Found in DevTools: script-src lacked the inline script's SHA-256 hash and googletagmanager.com; later, connect-src lacked Google's conversion endpoints (pagead2.googlesyndication.com, www.google.com, ad.doubleclick.net).
